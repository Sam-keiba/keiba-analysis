## 3. 差が大きかった指標とその原因
- **順位相関は計算方法で 0.374〜0.430 まで変わる。** リークのせいではない
  - 旧実測の 0.390 は「margin が同点の馬を馬番順で順位づけし、全レースを平均」で完全に再現できた
  - 同点が出るのは主に新馬戦（全頭未出走で margin が −0.5 にそろう）など、見分けられない 1,115 レース
  - 馬番順で切ると、そこが偶然の相関（平均ほぼ0）として入る
  - 平均順位で比べてそのレースを除くと 0.430、0 として数えると 0.392
- リークあり／なしの差が小さい理由: 今日のペースは、1995年以降の同じ条件の全レースの平均ラップから決めている（`race_forecast.average_laps`）。後のレースが混ざっても、平均の中の割合は小さい。ペースが変わる10.6%のレースでも、効き幅は最大±0.5段（PACE_WEIGHT）で、さらに馬のペース別の複勝率を通すので、段まで動くのは0.5%だけだった
- 頭数がわずかに違う（Aで±5頭程度）のは、旧実測の時点との DB の小さな差（取り込み直しなど）とみられる。中身は確認できない

## 4. 次のSTEP（人気ベースとの比較）への注意点
- **順位相関は今後「同点は平均順位・見分けられないレースは0」（per_race_all）を主にする**ことを提案する。旧方式は並び順に左右され、除く方式は見分けられないレースを捨てるぶん甘く出る。比べる相手（人気）も同じ計算にそろえる
- 人気ベースの予測には、**今回のレースの確定オッズ・人気は使えない**（発走後に確定する値。比較の基準としては使えるが、「発走前に分かる情報で作る」というルールの外になる）。基準として使うなら「市場の評価（上限の目安）」と明記する。results.win_odds は確定オッズで、発走前のオッズは DB に無い（odds テーブルには取得時点の列が無い）
- 回収率にも同じ確定単勝オッズを使う。実際に買える時点のオッズとはずれる
- tier は段と margin しか出さず、勝率（p_win）を出さない。evaluate.py の logloss・Brier・期待値で比べるには、margin を勝率に直す変換が要る（例: 学習期間でレース内のソフトマックスの温度を合わせる）。変換は学習期間（2023〜2025）だけで合わせ、2026年で評価する
- 新馬戦など全頭の margin がそろうレースが約9%ある。人気との比較ではここで差がつきやすいので、区分（新馬・未勝利・条件・重賞、クラシック／古馬）ごとにも出す
- 2026年の評価期間は約2,700レース。回収率の95%区間はかなり広くなるので、区間つきで見る
